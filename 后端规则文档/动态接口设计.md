## 功能概述

### 核心功能
1. **动态管理**：发布、查看、编辑、删除动态
2. **点赞功能**：对动态和评论进行点赞/取消点赞
3. **评论功能**：对动态进行评论、删除评论
4. **动态列表**：首页动态流、用户动态、电影相关动态

### 功能特点
- 动态可以关联电影、活动，或纯文字动态
- 支持多图片上传（最多4张）
- 实时统计点赞数、评论数
- 支持查询当前用户是否点赞
- 首页动态流显示关注人的动态
- **重要**：movieId是本地数据库电影ID，不是tmdbId

## 数据库改造

### 1. 动态表添加图片字段

```sql
-- 添加图片字段（JSON数组格式）
ALTER TABLE feeds 
ADD COLUMN images TEXT DEFAULT NULL COMMENT '动态图片（JSON数组，最多4张）' 
AFTER content;
```

**字段说明**：
- `images`: 存储图片文件名的JSON数组，如 `["img1.jpg", "img2.jpg"]`
- 前端需要拼接完整URL：`http://10.0.2.2:7070/uploads/{filename}`
- 最多支持4张图片

### 2. 点赞表改造（支持动态和评论点赞）

**重要**：不兼容旧格式，直接使用新结构

```sql
-- 删除旧表，重新创建（如果没有重要数据）
DROP TABLE IF EXISTS likes;

CREATE TABLE likes (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '点赞ID',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    target_type ENUM('FEED', 'COMMENT') NOT NULL COMMENT '点赞目标类型',
    target_id BIGINT NOT NULL COMMENT '目标ID（动态ID或评论ID）',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    UNIQUE KEY uk_user_target (user_id, target_type, target_id) COMMENT '用户-目标唯一索引',
    INDEX idx_target (target_type, target_id),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='点赞表';
```

**字段说明**：
- `target_type`: 点赞目标类型，FEED（动态）或 COMMENT（评论）
- `target_id`: 目标ID，根据target_type指向动态ID或评论ID
- 不再保留feed_id和comment_id字段

## 接口设计

### 1. 动态管理接口

#### 1.1 发布动态
```
POST /api/feeds
```

**请求体**：
```json
{
  "content": "刚看完这部科幻大片，视觉效果太震撼了！",
  "images": ["img1.jpg", "img2.jpg"],
  "movieId": 100,
  "eventId": null
}
```

**参数说明**：
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| content | string | 是 | 动态内容，最多2000字符 |
| images | array | 否 | 图片文件名数组，最多4张 |
| movieId | long | 否 | 关联电影ID（本地数据库ID，不是tmdbId） |

## DTO设计

### 1. FeedRequest（发布动态请求）
```java
public class FeedRequest {
    @NotBlank(message = "动态内容不能为空")
    @Size(max = 2000, message = "动态内容最多2000字符")
    private String content;
    
    @Size(max = 4, message = "最多上传4张图片")
    private List<String> images;
    
    private Long movieId;  // 本地数据库电影ID，不是tmdbId
    
    private Long eventId;
}
```

### 2. FeedResponse（动态响应）
```java
public class FeedResponse {
    private Long id;
    private UserSimpleDTO user;
    private MovieSimpleDTO movie;  // 包含本地ID和tmdbId
    private EventSimpleDTO event;
    private String content;
    private List<String> images;
    private Integer likeCount;
    private Integer commentCount;
    private Boolean isLiked;
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
}
```

## 业务逻辑

### 1. 发布动态流程
1. 校验参数（内容不能为空，图片最多9张）
2. 如果关联电影，检查电影是否存在
3. 如果关联活动，检查活动是否存在
4. 保存动态到数据库
5. 返回动态详情（包含用户、电影、活动信息）

### 2. 点赞动态流程
1. 检查动态是否存在
2. 检查是否已经点赞
3. 如果未点赞，创建点赞记录
4. 更新动态的点赞数（+1）
5. 返回点赞状态和最新点赞数

### 3. 取消点赞流程
1. 检查动态是否存在
2. 检查是否已经点赞
3. 如果已点赞，删除点赞记录
4. 更新动态的点赞数（-1）
5. 返回点赞状态和最新点赞数

### 4. 发表评论流程
1. 检查动态是否存在
2. 校验评论内容
3. 保存评论到数据库
4. 更新动态的评论数（+1）
5. 返回评论详情

### 5. 删除评论流程
1. 检查评论是否存在
2. 检查是否是评论作者
3. 删除评论（级联删除点赞）
4. 更新动态的评论数（-1）

### 6. 获取动态列表流程
1. 分页查询动态列表（按创建时间倒序）
2. 对每条动态：
   - 加载用户信息
   - 加载电影信息（如果有）
   - 加载活动信息（如果有）
   - 查询当前用户是否点赞
3. 返回动态列表

## 注意事项

### 1. 性能优化
- 使用分页查询，避免一次加载过多数据
- 使用JOIN FETCH优化关联查询，减少N+1问题
- 点赞数、评论数使用数据库字段存储，避免实时统计
- 考虑使用Redis缓存热门动态

### 2. 数据一致性
- 点赞/取消点赞时，同步更新动态的likeCount
- 发表/删除评论时，同步更新动态的commentCount
- 删除动态时，级联删除评论和点赞
- 使用事务保证数据一致性

### 3. 权限控制
- 只能编辑/删除自己的动态
- 只能删除自己的评论
- 所有接口都需要登录（Token认证）

### 4. 图片处理
- 图片文件名存储在数据库，前端拼接完整URL
- 支持多图上传，最多4张
- 图片存储格式：JSON数组字符串

### 5. 电影ID说明
- **重要**：movieId是本地数据库的电影ID，不是tmdbId
- 前端需要先调用 POST /api/movies/save 保存电影到本地数据库
- 然后使用返回的本地ID发布动态

### 6. 首页动态流
- 只显示当前用户关注的人发布的动态
- 如果没有关注任何人，返回空列表
- 按发布时间倒序排列

### 7. 错误处理
- 动态不存在：404
- 评论不存在：404
- 无权限操作：403
- 重复点赞：400
- 未点赞却取消：400
