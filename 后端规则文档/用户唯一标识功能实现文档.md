## 📋 需求说明

为用户表添加一个唯一标识字段（user_code）：
- 格式：4位数字（0001-9999）
- 按注册时间顺序自动生成
- 系统自动生成，用户不可修改
- 具有唯一性约束

### 潜在问题及解决方案

#### 问题1：并发安全 ⚠️

**问题描述**：
多个用户同时注册时，可能生成重复的编号。

**解决方案**：
```java

public synchronized String generateNextUserCode() {
    // synchronized关键字保证同一时刻只有一个线程执行
    // 数据库UNIQUE约束作为最后防线

```

**三重保障**：
1. `synchronized` 方法锁 - JVM级别
2. `@Transactional` 事务 - 数据库级别
3. `UNIQUE` 约束 - 数据库约束级别

---

#### 问题2：数量限制 ⚠️

**问题描述**：
4位数字只能支持0001-9999，最多9999个用户。

**解决方案**：
```java

    throw new RuntimeException("用户数量已达上限，无法注册新用户");
}
```

**扩展方案**（如果需要）：

#### 问题3：删除用户后的编号空缺 ⚠️

**问题描述**：
用户0005被删除后，编号会出现空缺。

**当前方案**：
不重用已删除的编号，保持编号的历史连续性。

**原因**：
- 避免混淆（新用户使用旧用户的编号）
- 保持审计追踪
- 简化实现逻辑

**如果需要重用**：
可以维护一个"已删除编号池"，优先从池中分配。

#### 问题4：性能问题 ⚠️

**问题描述**：
每次注册都要查询数据库获取最大编号。

**当前方案**：


**性能优化**（如果需要）：

### 4. Service层

#### UserCodeGeneratorService.java（新建）

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class UserCodeGeneratorService {
    
    private final UserRepository userRepository;
    
    @Transactional
    public synchronized String generateNextUserCode() {
        // 获取当前最大编码
        String maxUserCode = userRepository.findMaxUserCode();
        
        int nextNumber;
        if (maxUserCode == null || maxUserCode.isEmpty()) {
            nextNumber = 1;  // 第一个用户
        } else {
            nextNumber = Integer.parseInt(maxUserCode) + 1;
        }
        
        // 检查是否超过最大值
        if (nextNumber > 9999) {
            throw new RuntimeException("用户数量已达上限");
        }
        
        // 格式化为4位数字
        return String.format("%04d", nextNumber);
    }
}
```

#### 步骤2：为现有用户生成编码

```sql
-- 方法1：使用存储过程
DELIMITER $$
CREATE PROCEDURE generate_user_codes()
BEGIN
    DECLARE done INT DEFAULT FALSE;
    DECLARE user_id BIGINT;
    DECLARE counter INT DEFAULT 1;
    DECLARE cur CURSOR FOR SELECT id FROM users ORDER BY created_at ASC;
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = TRUE;
    
    OPEN cur;
    read_loop: LOOP
        FETCH cur INTO user_id;
        IF done THEN
            LEAVE read_loop;
        END IF;
        
        UPDATE users SET user_code = LPAD(counter, 4, '0') WHERE id = user_id;
        SET counter = counter + 1;
    END LOOP;
    CLOSE cur;
END$$
DELIMITER ;

-- 执行存储过程
CALL generate_user_codes();

-- 删除存储过程
DROP PROCEDURE generate_user_codes;
```

## 🎯 优缺点总结

### 优点 ✅

1. **实现简单**：代码量少，易于理解和维护
2. **并发安全**：synchronized + 事务 + 唯一约束三重保障
3. **顺序保证**：严格按注册时间顺序生成
4. **查询友好**：4位数字便于用户记忆和输入
5. **数据库友好**：使用VARCHAR(4)，存储空间小

### 缺点 ❌

1. **数量限制**：最多支持9999个用户
2. **性能瓶颈**：高并发时synchronized可能成为瓶颈
3. **编号不可重用**：删除用户后编号永久占用
4. **扩展性差**：达到上限后需要修改方案

```java
    public String generateNextUserCode() {
        // 使用Redis的INCR命令，原子性保证
```

```sql

SELECT LPAD(t.num, 4, '0') as missing_code
FROM (
    SELECT a.num FROM 
    (SELECT 1 as num UNION ALL SELECT 2 UNION ALL ... SELECT 9999) a
    LEFT JOIN users u ON LPAD(a.num, 4, '0') = u.user_code
```
