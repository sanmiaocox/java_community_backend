## 📊 系统设计说明

### 核心设计理念

1. **收藏夹类型明确**
   - 电影收藏夹（MOVIE）：只能收藏电影
   - 活动收藏夹（EVENT）：只能收藏活动
   - 不存在混合收藏夹

2. **看过功能独立**
   - 使用独立的 `watched_movies` 表
   - 不属于收藏夹系统
   - 支持评分和笔记功能

3. **多态关联设计**
   - 使用 `(collection_id, item_type, item_id)` 复合唯一约束
   - 即使电影ID和活动ID相同，也能正确区分
   - 查询时根据 `item_type` 决定去哪个表查询详细信息

### 业务规则

1. **用户注册时**
   - 自动创建"默认电影收藏夹"（MOVIE类型，系统收藏夹）
   - 自动创建"默认活动收藏夹"（EVENT类型，系统收藏夹）

2. **收藏限制**
   - 电影收藏夹只能添加电影
   - 活动收藏夹只能添加活动
   - 同一收藏夹中不能重复收藏同一项目

3. **系统收藏夹**
   - 不允许删除
   - 不允许修改名称和类型
   - 可以修改描述、公开性、封面图片

4. **权限控制**
   - 只能操作自己的收藏夹
   - 可以查看他人的公开收藏夹
   - 不能查看他人的私密收藏夹

## 🔧 API接口总览

### 收藏夹管理（6个接口）

1. `POST /api/collections` - 创建收藏夹
2. `GET /api/collections` - 获取用户的所有收藏夹
3. `GET /api/collections/type/{type}` - 获取指定类型的收藏夹
4. `GET /api/collections/{id}` - 获取收藏夹详情
5. `PUT /api/collections/{id}` - 更新收藏夹
6. `DELETE /api/collections/{id}` - 删除收藏夹

### 收藏项管理（5个接口）

1. `POST /api/favorites` - 添加收藏项
2. `GET /api/favorites/collection/{collectionId}` - 获取收藏夹中的所有收藏项
3. `GET /api/favorites/collection/{collectionId}/type/{itemType}` - 获取指定类型的收藏项
4. `DELETE /api/favorites/collection/{collectionId}/item/{itemType}/{itemId}` - 移除收藏项
5. `GET /api/favorites/check/{itemType}/{itemId}` - 检查是否已收藏

### 看过记录（6个接口）

1. `POST /api/watched` - 标记电影为看过
2. `DELETE /api/watched/{movieId}` - 取消看过标记
3. `PUT /api/watched/{movieId}` - 更新看过记录
4. `GET /api/watched` - 获取用户看过的所有电影
5. `GET /api/watched/check/{movieId}` - 检查是否看过
6. `GET /api/watched/count` - 获取看过的电影数量

**合计**: 17个新增API接口

## 📝 使用示例

### 示例1: 用户创建电影收藏夹并添加电影

```bash
# 1. 创建电影收藏夹
curl -X POST http://localhost:7070/api/collections \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "我的科幻片单",
    "type": "MOVIE",
    "isPublic": true
  }'

# 响应: { "id": 3, "name": "我的科幻片单", "type": "MOVIE", ... }

# 2. 添加电影到收藏夹
curl -X POST http://localhost:7070/api/favorites \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "collectionId": 3,
    "itemType": "MOVIE",
    "itemId": 100,
    "note": "非常喜欢这部电影"
  }'
```

### 示例2: 标记电影为看过

```bash
curl -X POST http://localhost:7070/api/watched \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "movieId": 100,
    "rating": 9.5,
    "note": "非常精彩的电影"
  }'
```

### 示例3: 收藏活动

```bash
# 1. 获取默认活动收藏夹（或创建新的活动收藏夹）
curl -X GET http://localhost:7070/api/collections/type/EVENT \
  -H "Authorization: Bearer {token}"

# 2. 添加活动到收藏夹
curl -X POST http://localhost:7070/api/favorites \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "collectionId": 2,
    "itemType": "EVENT",
    "itemId": 50
  }'
```

## 📌 重要说明

### 设计变更说明

原始设计中包含三种收藏夹类型（PLAYLIST/MIXED/WATCHED），经过讨论后调整为：

- ✅ **MOVIE**：电影收藏夹，只能收藏电影
- ✅ **EVENT**：活动收藏夹，只能收藏活动
- ✅ **看过功能**：独立的 `watched_movies` 表，不属于收藏夹系统

这样的设计更加清晰，职责分明：
- 收藏夹系统负责用户主动收藏的内容
- 看过系统负责记录用户的观影历史

### 数据兼容性

- 保留了 `favorites` 表中的 `movie_id` 字段用于兼容旧数据
- 新数据使用 `item_type` + `item_id` 字段
- 提供了完整的数据迁移方案
