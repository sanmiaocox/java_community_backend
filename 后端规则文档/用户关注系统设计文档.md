## 🗄️ 数据库设计

### follows（关注关系表）

```sql
CREATE TABLE IF NOT EXISTS follows (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '关注关系ID',
    follower_id BIGINT NOT NULL COMMENT '关注者ID（谁关注）',
    following_id BIGINT NOT NULL COMMENT '被关注者ID（关注谁）',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '关注时间',
    UNIQUE KEY uk_follower_following (follower_id, following_id) COMMENT '防止重复关注',
    INDEX idx_follower (follower_id) COMMENT '查询我关注的人',
    INDEX idx_following (following_id) COMMENT '查询关注我的人',
    CONSTRAINT fk_follows_follower FOREIGN KEY (follower_id) REFERENCES users(id) ON DELETE CASCADE,
    CONSTRAINT fk_follows_following FOREIGN KEY (following_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='用户关注关系表';
```

### 字段说明

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | BIGINT | 主键ID | 1 |
| follower_id | BIGINT | 关注者ID（主动方） | 用户A关注用户B，A是follower |
| following_id | BIGINT | 被关注者ID（被动方） | 用户A关注用户B，B是following |
| created_at | DATETIME | 关注时间 | 2026-02-28 10:00:00 |

### 关系示例

```
用户A(id=1) 关注 用户B(id=2)
→ follower_id=1, following_id=2

用户B(id=2) 关注 用户A(id=1)
→ follower_id=2, following_id=1

此时A和B互相关注，成为好友
```

## 🔍 查询逻辑

### 1. 查询我关注的人（关注列表）

```sql
-- 查询用户1关注的所有人
SELECT u.* 
FROM users u
INNER JOIN follows f ON u.id = f.following_id
WHERE f.follower_id = 1
ORDER BY f.created_at DESC;
```

### 2. 查询关注我的人（粉丝列表）

```sql
-- 查询关注用户1的所有人
SELECT u.* 
FROM users u
INNER JOIN follows f ON u.id = f.follower_id
WHERE f.following_id = 1
ORDER BY f.created_at DESC;
```

### 3. 查询好友列表（互相关注）

```sql
-- 方法1：使用子查询
SELECT u.* 
FROM users u
WHERE u.id IN (
    SELECT f1.following_id 
    FROM follows f1 
    WHERE f1.follower_id = 1
)
AND u.id IN (
    SELECT f2.follower_id 
    FROM follows f2 
    WHERE f2.following_id = 1
);

-- 方法2：使用JOIN（性能更好）
SELECT u.* 
FROM users u
INNER JOIN follows f1 ON u.id = f1.following_id AND f1.follower_id = 1
INNER JOIN follows f2 ON u.id = f2.follower_id AND f2.following_id = 1;
```

### 4. 检查关注状态

```sql
-- 检查用户1是否关注用户2
SELECT COUNT(*) > 0 AS is_following
FROM follows
WHERE follower_id = 1 AND following_id = 2;

-- 检查是否互相关注（是否为好友）
SELECT 
    (SELECT COUNT(*) FROM follows WHERE follower_id = 1 AND following_id = 2) > 0 AS i_follow_them,
    (SELECT COUNT(*) FROM follows WHERE follower_id = 2 AND following_id = 1) > 0 AS they_follow_me,
    (SELECT COUNT(*) FROM follows WHERE follower_id = 1 AND following_id = 2) > 0 
    AND (SELECT COUNT(*) FROM follows WHERE follower_id = 2 AND following_id = 1) > 0 AS is_friend;
```

### 5. 统计数量

```sql
-- 统计用户1的关注数
SELECT COUNT(*) AS following_count
FROM follows
WHERE follower_id = 1;

-- 统计用户1的粉丝数
SELECT COUNT(*) AS follower_count
FROM follows
WHERE following_id = 1;

-- 统计用户1的好友数
SELECT COUNT(*) AS friend_count
FROM follows f1
WHERE f1.follower_id = 1
AND EXISTS (
    SELECT 1 FROM follows f2 
    WHERE f2.follower_id = f1.following_id 
    AND f2.following_id = 1
);
```

## 🎯 设计优势

### 1. 单表设计的优点 ✅

- **简单高效**：只需一张表即可实现所有功能
- **查询灵活**：通过不同的查询条件实现各种需求
- **性能优秀**：合理的索引保证查询效率
- **易于维护**：表结构简单，逻辑清晰

### 2. 索引设计

```sql
-- 唯一索引：防止重复关注
UNIQUE KEY uk_follower_following (follower_id, following_id)

-- 普通索引：优化查询
INDEX idx_follower (follower_id)      -- 查询我关注的人
INDEX idx_following (following_id)    -- 查询关注我的人
```

### 3. 级联删除

```sql
-- 用户被删除时，自动删除相关的关注关系
CONSTRAINT fk_follows_follower FOREIGN KEY (follower_id) REFERENCES users(id) ON DELETE CASCADE
CONSTRAINT fk_follows_following FOREIGN KEY (following_id) REFERENCES users(id) ON DELETE CASCADE
```

## ⚠️ 注意事项

### 1. 业务规则

- ❌ 不能关注自己
- ❌ 不能重复关注（唯一索引保证）
- ✅ 可以关注任意存在的用户
- ✅ 互相关注自动成为好友

### 2. 性能优化

#### 查询优化
```java
// ✅ 使用分页查询
Page<Follow> follows = followRepository.findByFollowerId(userId, pageable);

// ❌ 避免查询所有数据
List<Follow> follows = followRepository.findAll();
```

#### 索引使用
```sql
-- ✅ 利用索引
SELECT * FROM follows WHERE follower_id = 1;  -- 使用idx_follower索引

-- ✅ 利用唯一索引
SELECT * FROM follows WHERE follower_id = 1 AND following_id = 2;  -- 使用uk_follower_following索引
```

### 3. 并发控制

使用唯一索引防止并发重复关注：
```sql
UNIQUE KEY uk_follower_following (follower_id, following_id)
```

如果同时发起两次关注请求，数据库会自动拒绝第二次插入。
